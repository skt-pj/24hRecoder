# Memoket Gem v0.7.112 — STOP transition regression fix (2026-10-14)

Authoritative spec: PCS Wiki 04 §34. Previous v0.7.107 deliberately removed the STOP-phase **second CONTROL 03**, since it was absent from the captured official app operation. The v0.7.110 test reinstated it and v0.7.111 kept it. This reintroduces a stale/contradicted hypothesis.

## Changes relative to v0.7.111
1. Preserve existing session/auth and START CONTROL 03 → 03ff → five-second timer unchanged.
2. When five-second STOP triggers, **do not send another CONTROL 03** and do not await another 03ff. Begin the known official-HCI DATA CCCD OFF transition on the same GATT connection.
3. Await exact DATA CCCD OFF success, then subscribe DATA ON **solely as the captured file-transfer subscription sequence**. This is not treated as STOP proof. Once DATA CCCD ON is written successfully, send CONTROL 010000 for the current-session file.
4. Add a pure, unit-tested state machine for strict DATA OFF→ON descriptor acknowledgement order; reject wrong/malformed callbacks.
5. Preserve current-session ownership, first DATA sequence, idle-only metadata 0200, CRC, finalization 03, durable local file save, filename-specific 05 ACK, 0501/00/0000. Do **not** remove the deletion ACK or touch old files.
6. Record bounded transfer progress evidence (1, 32, 128, 512, 1024... blocks) and independent state labels. Display explicit warning of historical stop-then-restart reports. No additional candidate STOP opcodes, recording-length truncation, arbitrary DATA cap, manual button prerequisite or diagnostic-only substitution.

## Known unresolved limitation
The true remote STOP opcode / exact official user-action HCI timestamp mapping is **not available** in currently accessible official capture bytes. DATA CCCD OFF→ON is a subscription sequence, **not proof that Gem hardware stopped**. In previous v0.7.108 this sequence did not produce a confirmed stop; v0.7.88 includes a user report of stop followed by immediate unexpected re-recording. This build fixes the concrete STOP-phase extra-03 regression, but cannot be claimed as a hardware-verified five-second recording stop. It must not display "Gem STOP successful" simply due to CCCD or DATA transfer, or assert real flash deletion based only on 0501. Hardware validation remains needed.

## Regression contract
- Only the post-handshake START path sends 03 before the file-finalize phase.
- Five-second timer is preserved.
- Descriptor order OFF(0000)→ON(0100) checked; invalid order rejected.
- Finalization 03 and post-save 05 preserved.
- No 05 for CRC/size mismatch, incomplete DATA, wrong file or save failure.
- No manual Gem STOP button inserted.
